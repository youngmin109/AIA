PART 1 · SCOPE

무엇을 보호하는가

AIA는 Codex CLI의 실행을 대신하는 Agent가 아니다. 사용자가 이미 만든 Workspace를 보호 범위로 정하고, 지원된 Codex 실행 경로에서 관찰 가능한 행위를 수집·판정·집행한다.

핵심 원칙
Agent의 자기 보고나 내부 추론은 보안 증거로 사용하지 않는다. AIA가 근거로 삼는 것은 Codex Hook, Windows 파일시스템, 관리 대상 Process Tree에서 관찰한 제한된 Runtime Evidence다.

PART 2 · PROTECTED RUN

Protected Run은 어떻게 시작되는가

AIA는 먼저 보호 환경을 준비하고, 준비가 통과된 뒤에만 지원된 Codex CLI를 자식 프로세스로 시작한다. Workspace는 AIA가 만들지 않고 사용자가 선택한 기존 폴더만 사용한다.

1

Workspace와 정책을 확정한다

사용자가 지정한 기존 Workspace가 존재하는지 확인하고, 정책 Profile과 버전을 읽어 이번 Session에 고정한다.

정책 파일이 실행 중 바뀌어도 현재 Run은 시작 시점의 Active Policy Freeze를 사용한다.
2

Lease와 Safe Checkpoint를 준비한다

Workspace Lease로 동시에 두 실행이 같은 Workspace를 점유하지 않게 하고, Recovery·Integrity에 사용할 기준 상태를 기록한다.

Checkpoint는 복구의 기준선이며, 모든 변경이 반드시 복구된다는 보장은 아니다.
3

세 센서와 Readiness를 확인한다

Hook Sensor, File Sensor, Process Sensor를 준비하고 필수 사전 조건이 충족되었는지 Readiness Barrier에서 확인한다.

Hook 설치와 Codex에서의 Trust, 실제 Session-bound Event 관찰은 서로 다른 상태다.
4

Codex를 보호된 자식 프로세스로 실행한다

AIA가 지원된 실행 경로를 직접 시작하고 Root PID와 생성 시각을 등록한다. 이후 Process Sensor는 등록된 관리 트리만 관찰한다.

Windows 전체 프로세스를 AIA가 소유한다고 주장하지 않는다.
5

관찰·판정·집행을 연결한다

Raw Evidence를 Normalized Action으로 변환하고, Policy Evaluation과 Attribution을 거쳐 Enforcement Gate가 결과를 결정한다.

Process Sensor 관찰만으로 특정 파일을 어느 도구가 썼다고 단정하지 않는다.
6

종료 후 복구·무결성·감사를 확정한다

필요한 Recovery를 수행하고 Integrity를 별도로 검증한 뒤, 해시와 manifest를 포함한 Result Bundle을 확정한다.

PART 3 · SENSOR EVIDENCE

Hook · File · Process Sensor

세 센서는 서로 다른 관찰 지점을 담당한다. 하나의 센서가 시스템 전체의 사실을 대신 증명하지 않으며, AIA는 각 Evidence Source와 한계를 분리해서 기록한다.

Hook Sensor

사전 관찰·관문

Codex PreToolUse 요청을 받아 제한하고, 검증된 정책에 따라 실행 전 응답을 반환한다.

  • AGENT_HOOK Raw Evidence 기록
  • 정책 위반은 deny 또는 contain 경로
  • Trust와 Session-bound Event를 별도 검증
  • deny 응답만으로 실제 부작용 없음은 주장하지 않음

File Sensor

변화 관찰

보호 Workspace에서 보이는 파일시스템 변화를 관찰하고 Checkpoint와 결과를 연결한다.

  • CREATE · MODIFY · DELETE · MOVE · RENAME
  • FILESYSTEM_WATCHER Evidence
  • 관찰과 Recovery를 분리
  • 복구 뒤 Integrity를 별도로 검증

Process Sensor

관리 트리 관찰

AIA가 등록한 Root와 자식 Process Tree를 PID·생성 시각과 함께 관찰한다.

  • PROCESS_RUNTIME Evidence
  • PID 재사용을 생성 시각으로 구분
  • unrelated 프로세스는 관리 대상 밖
  • 관찰 사실과 정확한 파일 작성자 귀속을 분리
센서의 관계
Hook은 실행 전 요청을 보고, File은 실제로 보이는 파일 변화를 보고, Process는 관리 트리의 실행 상태를 본다. AIA는 이 세 가지를 Evidence ID와 시간·Session 정보로 연결해 사건을 설명한다.

정책 판정은 어떻게 만들어지는가

정책은 행위의 의미를 추측하는 규칙이 아니라, 정규화된 Operation·Asset Type·Path 또는 Command Pattern을 비교하는 결정 규칙이다.

3.2 · AUDIT LINEAGE

Evidence는 어떻게 결과가 되는가

원시 관찰, 정규화된 행위, 정책 판정, 귀속, 집행을 한 값으로 덮어쓰지 않는다. 각 단계의 근거를 연결해 나중에 결과를 다시 설명할 수 있게 한다.

Raw Evidence센서가 관찰한 원시 사실 · Evidence ID
↓
Canonical ActionOperation · Target · Source · Completeness
↓
Policy Evaluation + AttributionRule 결과와 Session 연결 수준
↓
Enforcement + RecoveryPreTool deny · Process termination · Restore
↓
Integrity + Audit검증 결과 · manifest · Result Bundle
Result Bundle이 권위 있는 종료 결과다.
Session binding, 필수 산출물, 해시, Evidence 참조를 확인한 뒤에만 VALID 결과로 표시한다. 실행 중 화면의 상태 스냅샷과 완료된 Bundle은 같은 의미가 아니다.

4.3 · CLAIM BOUNDARY

현재 구현과 주장 범위

오픈소스 제품의 신뢰성은 되는 일을 크게 말하는 데서 나오지 않는다. 현재 실제로 검증된 것과 아직 지원하지 않는 것을 같은 화면에서 분리해 보여준다.

✓
현재 구현
Codex CLI Protected Run, 정책 고정·판정, Hook Sensor, File Sensor, Process Sensor, Evidence Bundle, Recovery·Integrity 결과, 로컬 콘솔을 제공한다.
✓
현재 확인 가능한 보호
지원된 Codex PreToolUse 경로에서 정책 위반을 사전 차단하고, 실제 도구 실행 여부가 확인된 경우에만 BLOCKED / SUCCEEDED로 표시한다.
×
지원하지 않는 범위
MCP, Claude, 임의의 외부 Agent, 네트워크 보안, OS 전체 모니터링, 보호 범위 밖 도구는 현재 제품 보호 대상으로 주장하지 않는다.
×
의도 해석 금지
AI의 Chain-of-Thought, 내부 의도, scheming 여부를 분석하거나 LLM으로 보안 판정을 만들지 않는다.
×
귀속 한계
Process Sensor가 프로세스를 관찰했다는 사실만으로 특정 프로세스가 특정 파일을 작성했다고 증명하지 않는다.
