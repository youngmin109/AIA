# AIA 0.1.30 사용 안내

## 정책

정책의 네 가지 템플릿과 사용자 지정은 한 줄에 표시한다. 좁은 창에서는 가로로 스크롤한다.
별도 상세보기 목록을 제거했으며 템플릿 안내와 명령 판정 미리보기로 확인한다.
‘변경 통제 강화’의 루트 `.env` 읽기는 금지가 아닌 감사다. 비밀값 자체를 검사하는 DLP 제품은 아니다.

사용자 지정은 표준 보호의 복사본으로 시작한다. 규칙을 펼쳐 파일 경로 또는 명령 패턴, 우선순위,
행동별 허용·감사·금지를 설정한다. 확인란을 읽고 ‘규칙 검증하고 저장’을 누른다.
판정 미리보기는 명령을 실행하지 않는다. 새 보호 실행에서 사용자 지정을 선택하면 저장된 파일을
다시 검증해 실행용 정책으로 고정한다. 이미 실행 중인 정책은 바뀌지 않는다.

## 자동 및 수동 복구 지점

실행 전 기준점은 계속 보존한다. 추가 지점은 자동 차단 대응의 기준을 바꾸지 않는다.
Codex app-server 작업이 정상 완료되고 대기 상태에 도달하면 자동 저장을 시도한다.
센서·Hook 건강, 미처리 확인 요청 없음, 위반·미확정 판정 없음, 지원 범위 밖 도구 사용 없음,
파일 이벤트 처리와 저장 전후 상태 일치가 필요하다. 변화가 없으면 생략한다.
조건 미충족 시 ‘안전한 지점’이라고 표시하지 않으며, 저장 보류 이유를 보여준다.

기록 → 해당 실행 → 복구 지점에서 이름을 입력하고 ‘현재 복구 지점 저장’을 누를 수 있다.
작업 중에는 저장을 거절하므로 작업 완료 후 다시 시도한다. 실행 종료 후 각 지점의
‘변경 미리보기 · 복구’를 누르고 영향 경로를 확인한다. 이 복구는 현재 폴더의 새 파일 제거와
변경·삭제 파일 복원을 포함할 수 있다. 확인란에 동의해야 실행하며 Lease와 미리보기 해시를 재검증한다.
복원 성공과 SHA-256 무결성 검증 성공은 따로 표시한다. 원래 감사 결과는 보존한다.

지점은 세션당 최대 50개다. 자동 지점은 최근 5개만 남기고 더 오래된 자동 지점은 지운다(수동 지점과 실행 전 기준점은 지우지 않는다). 같은 실행의 이전 기준점·지점과 내용이 같은 파일은 다시 복사하지 않고 하드 링크로 공유하므로, 지점이 늘어도 바뀐 파일만큼만 공간이 는다. 지점마다 전체 폴더 구조와 파일 해시를 그대로 갖고 저장할 때 모든 파일을 다시 검증하므로 복구와 검증 방식은 같다. 파일 1,000개·50MB 미만인 작업 폴더는 요청이 끝날 때마다, 그보다 크고 파일 2만 개·2GB 미만인 폴더는 최대 10분에 한 번 자동 저장한다. 그보다 큰 폴더는 자동 저장을 하지 않고 이유를 알린다. 자동 저장 중에 보낸 요청은 저장이 끝날 때까지 최대 30초 기다렸다가 전달한다. 저장 일관성은 코드 안전성 보증이 아니다.
외부 프로그램의 쓰기, 파일 이벤트 전달 지연과 보호 범위 밖 도구는 한계다.
실제 Codex의 새로운 자동 지점 저장 흐름은 별도 실사용 검증이 필요하다.

## 바탕화면 가디언

설정 → 가디언 펫을 켜면 독립 창을 띄운다. 그림을 끌어서 옮길 수 있다.
설정 → 펫 크기에서 작게·보통·크게를 선택한다. 선택은 이번 실행 동안만 유지하고, 앱을 다시 켜면 보통 크기로 돌아간다(데스크톱 앱은 실행마다 화면 설정 저장소를 새로 만든다).
‘AIA 열기’와 ‘접기’는 상태 안내 상자 안의 작은 버튼으로 표시한다.
앱을 최소화해도 남는다. ‘AIA 열기’로 돌아간다.
‘접기’를 누르면 펫이 그 자리에서 작은 동그라미로 줄어든다. 동그라미를 누르면 그 자리에서 다시 펼쳐지고, 끌면 옮겨진다.
동그라미 테두리는 상태 색을 유지한다(확인 필요는 노란색, 차단은 깜박이는 빨간색). 펫을 완전히 끄려면 설정 → 가디언 펫을 끈다.
앱 완전 종료 시 함께 종료하므로 앱 종료 후 상주 보안 서비스가 아니다.
3초 간격으로 실제 상태를 조회하며 연결 실패는 확인 필요로 표시한다.
실행이 없으면 ‘실행 대기’이지 ‘정상 보호 중’이 아니다. 짧은 사건을 모두 알리는 Windows 알림 센터 기능은 아니다.

## 실행과 연결

배포 폴더의 `AIA/AIA.exe`를 실행한다. `_internal`을 함께 보존해야 한다.
새 패키지로 Hook 실행 경로가 바뀌면 설정 화면의 설치 → Codex `/hooks`에서 직접 Trust → 연결 검증 순서를 따른다.
AIA는 사용자의 Trust를 대신 승인하지 않는다. 과거에 준비 완료였더라도 경로 변경 후 다시 확인할 수 있다.

이번 작업은 `feature/policy-checkpoints-desktop-guardian`의 로컬 개발 내용이며 main 병합·원격 배포와는 별개다.
