# PR #27 검토 결함 수정 (2026-10-13)

## 범위

GitHub #28(권한), #29(복구/정리 경합), #30(삭제 결과·용량)을 직접 수정한다.
Codex 외부 도구 제어·보호 경로 선택·증분 기준점·UI 활동 띠 등 JH 기능은 유지한다.

## 권한

- 기본값은 기존 보호 기준인 `workspace-write/on-request/user`를 유지한다. 전체 권한은 명시적으로 고르는 옵션이다.
- 선택은 PENDING, 전송 직전은 SUBMITTING, Codex 접수는 ACKNOWLEDGED, 전송 결과 불명은 UNCONFIRMED로 분리한다.
- `permission_changes`에는 변경 ID, 이전/이후 모드, 요청·전송·접수 시각과 상태만 저장한다. 대화·명령 원문은 저장하지 않는다.
- 확대 요청은 RPC 전에 보호 예외를 strict 저장한다. 저장 실패 시 전송하지 않는다. 접수 실패/시간 초과는 정상 보호로 복귀시키지 않는다.
- 선택만 하고 취소한 모드는 `*_used`로 표시하지 않는다. 접수된 설정도 실제 적용 검증으로 주장하지 않는다. 시작 시 정책 관찰은 변경 후 NOT_OBSERVED로 표시한다.
- 전체 권한·자동 검토·중간 권한 확대는 DEGRADED이며, 제한 모드로 되돌려도 이번 실행의 예외는 유지한다.
- 확장된 권한을 가진 Codex가 AIA 기록 폴더까지 접근하는 것을 OS 수준에서 막는 기능은 아니다. Hook 밖 도구·네트워크·Workspace 밖 변경은 기존 제한사항을 따른다.

## 복구·정리

- 복구의 검증→복사→무결성 확인과 기준점 삭제는 같은 서비스의 `_manual_restore_lock`을 공유한다. 복구 중 정리는 대기한다.
- 앱을 켜는 것만으로 기존 복구 사본을 삭제하지 않는다. 설정에서 삭제 범위를 확인한 뒤 수동으로 정리한다.
- 실제 삭제 실패는 failed_runs로 반환하고 완료 marker를 쓰지 않는다. 재시도할 수 있다.
- 하드링크는 inode마다 한 번만 집계한다. 지우지 않는 경로에 링크가 남으면 확보량으로 세지 않는다. 크기는 파일 논리 바이트 기준이며 압축·희소 파일의 디스크 할당량을 측정하는 것은 아니다.
- 이 잠금은 동일 AIA 서비스의 작업을 조정한다. 외부 프로세스가 기록 폴더를 직접 수정하는 행위까지 통제하는 OS 잠금은 아니다.

## 검증 항목

- 전송 직전 기록, 저장 실패 시 RPC 미전송, 시간 초과, 예약 변경 취소, 권한 축소 후 예외 유지.
- 가짜 app-server로 실제 JSON-RPC 전달 순서 및 오래된 effective 필드 무효화.
- 복구 잠금과 삭제의 동시 실행, Windows에서 실제 열린 파일의 삭제 실패, 재시도, marker 쓰기 실패, 공유/외부 하드링크의 용량.
- Python 전체 테스트, 프론트엔드 테스트·lint·build, Windows 패키지 빌드 및 자체 진단.

실제 Codex 전체 시나리오·장시간 GUI·다른 PC 검증은 이 회귀 테스트로 대체하지 않는다.
