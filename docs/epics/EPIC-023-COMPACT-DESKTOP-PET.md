# EPIC-023: 작은 바탕화면 아이아 펫

## 범위

- 작업표시줄과 Alt+Tab에는 AIA 본창만 표시한다. 펫은 별도의 소유자 없는 투명 도구 창으로 유지해 본창 최소화 후에도 남는다.
- 펫 하단의 넓은 상태 카드와 열기·접기 버튼을 제거한다. 실제 관찰 상태에 따라 그림을 바꾸며 작은 상태 점과 툴팁만 유지한다.
- 아이아 클릭은 본창 열기, 드래그는 위치 이동이다. 작은 `?`는 본창의 기존 도움말·오류 신고를 연다.
- 설정에서 크기를 70~140%, 5% 단위의 가로 슬라이더로 조절한다. 이전 small/medium/large 설정은 80/100/130%로 변환한다.
- 펫 창의 크기 변경은 현재 모니터 작업 영역 안으로 제한한다.

## 제외 범위 / 불변식

- 정책, Hook, 복구, 감사 형식과 보안 판정은 변경하지 않는다.
- 도움말과 오류 신고는 기존 사용자 조작 흐름이다. 오류를 자동 전송하지 않는다.
- 펫은 읽기 전용 상태 관찰자다. 본창의 heartbeat를 대신하지 않고, 연결 실패를 정상 보호로 표시하지 않는다.
- 앱 완전 종료 시 펫도 종료한다. 브라우저 내부 펫의 이동·도움말 동작은 유지한다.

## 검증

- Windows 확장 스타일에서 TOOLWINDOW 설정, APPWINDOW 제거, NOACTIVATE/TOPMOST/LAYERED 보존 테스트.
- 크기 입력 검증, 저장값 이전, 모니터 경계, 본창·도움말 라우팅 테스트.
- Python/프론트엔드 전체 테스트 및 Windows 패키지 빌드.
- 실제 Windows에서 최소화 후 펫 유지, 클릭 복귀, 드래그, `?` 도움말, 오류 신고, 슬라이더 확인.

main 병합은 JH 리뷰 후 별도 승인으로 진행한다.

- Windows AIA.exe 및 aia-cli.exe 빌드 성공. AIA.exe self-test: 8개 PASS, 실제 Codex 실행 검증은 NOT_RUN.

- 도구 창인 펫은 Windows 자동화 도구의 창 목록에서 제외된다. 펫 위 좌표 입력도 다른 창으로 인식되어 거부됐다. 따라서 펫 클릭→본창 복귀, `?` 클릭→도움말 열기, 드래그와 최소화 후 표시 유지는 **실제 마우스로 추가 확인 필요**하다. 브리지 라우팅·창 스타일·소유자 없는 창 구조는 단위 테스트로 검증했다.
- 이전 실행 중인 AIA와 그 세션은 수정·종료하지 않았다. 검토 빌드는 `dist/windows-pet-compact-review`에 분리했으며 Git에는 올리지 않는다.
