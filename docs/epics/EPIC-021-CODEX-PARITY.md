# EPIC-021 — Codex 작업 경험 보강 (작업 계획)

> 상태: **진행 중** (브랜치 `feature/codex-parity`, 2026-10-07 시작). 진행 기록은 `docs/codex-parity/PROGRESS.md`.

## 목적

보호 실행 안에서도 Codex 앱처럼 일할 수 있게, 자주 쓰는 기능 다섯 가지를 붙인다.
상업용 제품이 아니므로 범위는 아래 다섯 가지와, 2026-10-07에 발견한 시작 속도 문제 보완으로 고정한다.

1. Codex가 사용자에게 되묻는 요청 처리 (지금은 "지원 안 함"으로 거절됨)
2. 사용량, 모델 고르기, 작업 계획, 바뀐 내용 보기
3. 빗금(/) 명령 목록: Codex 기본 명령 일부 + AIA 보안 명령
4. 이전 대화 이어하기 (AIA로 연 대화만)
5. 커넥터 목록 (보기만, 보안 표시 포함)
6. 시작 단계 보완: 진행 단계 표시, 큰 폴더 미리 알림, "준비 중"으로 남은 실행 정리

## 사용자가 정한 것 (2026-10-07)

- **권한 추가 요청:** 실제 Codex처럼 사용자 선택에 전적으로 맡긴다(이번 요청만 / 이번 실행 내내 / 거절).
  - 사용자는 YOLO 모드 사용을 지향한다.
  - 허용하면 보호 범위가 넓어진 사실을 화면과 감사 기록에 남긴다.
- **이전 대화 목록:** AIA를 통해 연 대화만 보여준다.
  - Codex 쪽 필터(`thread/list`의 `originators`)는 로컬 앱 서버에서 거부된다(스키마 설명으로 확인).
  - 그래서 AIA가 실행마다 Codex 대화 번호를 직접 기록하고, 그 기록으로 목록을 만든다.
- **시작 속도 보완 세 가지는 이 EPIC에 함께 넣는다.**

## 출발점 (2026-10-07 확인)

- **Codex 버전**
  - AIA가 실제로 띄우는 Codex는 Codex 앱에 들어 있는 `codex-cli 0.160.0`이다(`%LOCALAPPDATA%\OpenAI\Codex\bin\...`).
  - PATH의 npm Codex는 0.157.1이다.
  - 0.157.1의 `codex app-server generate-json-schema`로 뽑은 메서드·알림은 188개이고, AIA는 그중 15개 정도만 쓴다.
  - TASK-101에서 0.160.0 스키마로 다시 확인한다.
- **Codex가 이미 제공하는 것:** 다섯 가지 모두 Codex에 있다. 새로 만들 것은 **연결 코드와 화면**이다.

## 지켜야 할 것 (보안 불변식은 바꾸지 않는다)

- **보호 범위는 사용자가 직접 고를 때만 넓어진다.**
  - 권한 추가 요청(TASK-107)에서 사용자가 허용한 경우만 넓힌다. 그 사실은 화면, 결과, 감사 기록에 남긴다.
  - 그 밖에는 몰래 넓히는 길을 열지 않는다.
    - `turn/start`에서 덮어쓸 수 있는 값은 `model`과 `effort` 두 가지뿐이다(서버 쪽 허용 목록).
    - `approvalPolicy`, `sandboxPolicy`, `cwd`, `approvalsReviewer`는 보내지 않는다.
    - `thread/resume`에도 보호 폴더, 샌드박스, 승인 정책을 그대로 강제한다.
- **에이전트를 거치지 않는 직접 실행 기능은 붙이지 않는다.** 실행 전 검사와 감시를 건너뛸 수 있기 때문이다.
  - 대상: `thread/shellCommand`, `command/exec`, `fs/*` 쓰기, `mcpServer/tool/call`, `plugin/install`, `marketplace/*`, `thread/revert`
  - 이것들은 Codex 앱에서 쓰도록 안내만 한다.
- **비밀값을 남기지 않는다.**
  - 질문 요청의 비밀 답(`isSecret`)과 외부 도구 입력값은 이벤트 기록, 감사, 로그, 진단 정보 어디에도 남기지 않는다.
  - 화면에서도 가린다.
- **대화 원문은 메모리에서만 다룬다** (⑩ 설정의 개인정보 문구와 같게).
  - 바뀐 내용(diff)과 질문·답은 대화 영역에만 보이고 저장하지 않는다.
  - 저장하는 것은 대화 번호와 이름뿐이다.
  - AIA 보호 패널에는 지금처럼 경로와 개수만 보인다.
- EPIC-020의 문구 규칙(차단 판정 ≠ 막음 등)을 그대로 따른다.
- **실험 기능은 버전에 기대지 않는다.**
  - `requestUserInput`은 실험 기능이라 형식이 바뀔 수 있다.
  - 모르는 형식이 오면 지금처럼 "지원 안 함"으로 되돌아가게 한다. Codex가 멈추지 않는 것이 우선이다.
- 새 의존성은 넣지 않는다. 바뀐 내용 색칠과 명령 목록은 직접 만든다.

### 1단계 · 시작 단계 보완 (2026-10-07 발견, 시연에 바로 영향)

- **TASK-102 시작 진행 단계 표시**
  - **서버:** 실행 상태에 시작 단계를 싣는다.
    - 단계: 작업 폴더 확인 → 기준점 저장(파일 n/N) → 감시 시작 → 준비 확인 → Codex 시작
    - 기준점 저장은 파일 수 기준 진행률을 준다.
  - **화면:** 작업창 대기 화면과 ② 실행 중 홈에 지금 단계와 경과 시간을 보여준다.
    - "준비됨"은 그 단계가 실제로 끝났을 때만 쓴다.
- **TASK-103 큰 폴더 미리 알림과 느린 구간 측정**
  - **알림:** ④ 새 실행 시트에서 폴더를 고르면 파일 수와 크기를 빠르게 센다.
    - 상한을 둔다(예: 5,000개 또는 2초에서 멈춤).
    - 기준을 넘으면(예: 1,000개 또는 50MB) "시작까지 오래 걸릴 수 있어요"라고 알리고, 하위 폴더를 고르라고 안내한다.
  - **측정:** 감시 시작 뒤 Codex 시작까지 42초가 어디서 걸리는지 측정한다.
    - 후보: 준비 확인(`ProtectionReadinessBarrier`), 파일 감시 기준선, 실행기 준비
    - 보호를 약하게 하지 않는 선에서만 줄인다.
  - **결과(2026-10-07):** 폴더 전체 해시가 약 6번이다. 기준점 저장 4번, 준비 확인 1번, Codex 띄우기 직전 재확인 1번.
    - 띄우기 직전 재확인은 확인과 사용 사이의 틈을 막는 보안 검사라 줄이지 않았다.
    - 대신 단계 이름과 큰 폴더 미리 알림으로 안내한다.
    - 더 줄이려면 보안 불변식 변경으로 따로 정한다.
- **TASK-104 "준비 중"으로 남은 실행 정리**
  - 앱이 다시 켜질 때, 주인 프로세스가 없는 "준비 중" 실행을 "중단됨(준비 중 앱 종료)"으로 정리한다.
  - 기존 고아 실행 정리(`runtime_reconciliation`)와 같은 방식으로 한다.
  - 작업 폴더 임대가 남아 있으면 기존 규칙대로 푼다.
  - 감사 기록에는 실제로 확인한 사실만 남긴다.
  - **결과(2026-10-07):** 서버는 이미 이런 실행을 고아로 정리 확인한다(`NOT_STARTED`, `acknowledged`).
    - 저장된 상태를 "중단됨"으로 고쳐 쓰면 마무리 절차를 거친 것처럼 되므로 그대로 둔다.
    - 화면(기록, 홈, 가디언)에서 "준비 중 중단"으로 보여준다.

### 2단계 · 되묻기 (빈틈 메우기)

- **TASK-105 질문 요청 (`item/tool/requestUserInput`)**
  - **서버**
    - 대기 중인 질문을 저장하고 `question.requested` 이벤트를 낸다. 이벤트에는 질문, 선택지, "기타" 허용 여부, 비밀 여부, 자동 해결 시간을 담는다.
    - WebSocket에 `question_answer` 메시지를 추가한다. 응답 형식은 `{answers: {질문id: {answers: [...]}}}`이다.
    - `serverRequest/resolved`가 오면 대기 중인 질문을 지운다.
  - **화면**
    - 대화 안에 질문 카드를 만든다. 선택지는 버튼으로, "기타"는 입력칸으로, 비밀은 가린 입력칸으로 둔다.
    - 자동 해결 시간이 있을 때만 남은 시간을 보여준다.
  - **테스트:** 비밀 답이 이벤트·로그에 남지 않는지, 모르는 형식이면 거절로 되돌아가는지 확인한다.
- **TASK-106 외부 도구 입력 요청 (`mcpServer/elicitation/request`)**
  - **form 모드:** 단순 필드(문자, 숫자, 참·거짓, 선택)만 입력 폼으로 그린다. 그 밖의 형식은 "거절"만 할 수 있다.
  - **url 모드:** 주소의 도메인을 크게 보여준다. 사용자가 확인을 눌러야 바깥 브라우저로 연다.
  - **응답:** 수락, 거절, 취소 셋 중 하나로 답한다.
  - **감사:** 서버 이름과 결과만 남긴다.
- **TASK-107 권한 추가 요청 (`item/permissions/requestApproval`) — 사용자 선택**
  - **화면:** 대화 안에 승인 카드를 띄운다.
    - 요청 내용을 쉬운 말로 보여준다: 어느 폴더를 읽기/쓰기로 넓히는지, 인터넷을 켜는지, Codex가 적은 이유
    - 선택지는 "이번 요청만 허용"(`scope: turn`), "이번 실행 내내 허용"(`scope: session`), "거절"(빈 권한)이다.
    - 미리 골라진 선택지 없이 사용자가 직접 누르게 한다.
  - **보호 범위 표시**
    - 작업 폴더 밖 쓰기를 허용하면 카드와 보호 패널에 "이 폴더는 AIA 기준점·복구 범위 밖"이라고 알린다.
    - 인터넷 허용도 같은 방식으로 알린다.
    - 보호 패널과 ③ 결과에 "이번 실행에서 넓힌 권한" 줄을 둔다.
  - **감사:** 요청 내용, 사용자 선택, 범위, 시각을 기록한다. 폴더 경로는 기록하고 비밀값은 없다.
  - **테스트:** 세 가지 선택이 각각 올바른 응답 형식이 되는지, 허용 기록이 결과에 나오는지 확인한다.

### 3단계 · 눈에 보이는 것

- **TASK-108 사용량**
  - **언제 가져오나:** 실행을 시작할 때 `account/rateLimits/read`로 읽는다. `account/rateLimits/updated` 알림이 오면 갱신한다.
  - **이번 대화 사용량:** `thread/tokenUsage/updated`로 받는다.
  - **어디에 보이나**
    - 작업창 위쪽에 작은 표시("5시간 한도 ○% 남음")를 둔다.
    - 누르면 주간 한도, 초기화 시각, 이번 대화 사용량이 나온다.
  - **값이 없을 때:** API 키 로그인처럼 한도 정보가 없으면 숨긴다.
- **TASK-109 모델·생각 깊이 고르기**
  - `model/list`로 목록을 받는다(숨김 모델 제외).
  - ④ 새 실행 시트에서 고르면 `thread/start`의 `model`로 넘긴다. `record.model`은 이미 있다.
  - 작업창에서도 바꿀 수 있다. 이때는 다음 요청부터 `turn/start`의 `model`·`effort`로 적용하고, 서버는 허용 목록으로 걸러낸다.
  - 결과와 기록에 실제로 쓴 모델을 남긴다(`thread/start` 응답 값).
- **TASK-110 작업 계획**
  - `turn/plan/updated`를 받아, 대화 위에 접을 수 있는 체크 목록으로 보여준다. 각 단계에는 상태(대기, 진행, 완료)를 표시한다.
- **TASK-111 바뀐 내용 보기**
  - `turn/diff/updated`를 받아, 대화의 파일 카드에 "바뀐 내용 보기" 펼침을 붙인다. 추가 줄과 삭제 줄은 색으로 구분한다.
  - 아주 크면 앞부분만 보여주고 "일부만 표시"라고 알린다(예: 2,000줄).
  - 보호 패널은 지금처럼 경로만 보여준다.

### 4단계 · 빗금(/) 명령

### 5단계 · 이전 대화 이어하기 (AIA로 연 대화만)

- **TASK-115 대화 번호 기록**
  - Codex 대화가 준비되면(`session.ready`), 실행 폴더에 대화 번호와 시작 시각을 저장한다.
  - 이름이 생기면(`thread/name/updated`) 이름도 저장한다.
  - 기록·결과 API에 대화 번호를 싣는다.
  - 이 기능 전에 끝난 실행은 번호가 없어서 목록에 나오지 않는다. 문서에 적는다.
- **TASK-116 이어하기**
  - **고르기:** ④ 새 실행 시트에 "새 대화 / 이전 대화 이어하기"를 둔다.
    - 목록은 AIA 실행 기록 중 대화 번호가 있는 것만 보여준다. 날짜, 작업 폴더, 대화 이름, 결과 상태를 표시한다.
  - **시작:** 고르면 그 실행의 작업 폴더로 새 보호 실행을 시작한다.
    - `thread/start` 대신 `thread/resume`을 쓰고, 보호 폴더·샌드박스·승인 정책은 강제한다.
  - **화면 복원:** 이전 대화 내용은 응답의 turns 또는 `thread/read`로 다시 그린다.
  - **감사:** 감사 기록에 "이어한 대화(이전 실행 id)"를 남긴다.
    - 화면에는 "이전 대화에서 일어난 일은 이번 보호 기록 범위 밖"이라고 적는다.
  - **실패 처리:** Codex 쪽에서 대화가 지워졌으면 "이 대화는 더 이상 이어할 수 없어요"라고 알리고 새 대화로 시작하게 한다.
