# AIA MVP 제한사항

2026-10-02 개선 작업본의 복구 범위, 표시 인덱스 제한, 로컬 브라우저 경계와
미완료 검증은 [개선 작업 기록](PRODUCT-UPDATE-2026-10-02.md)에 별도로 명시한다.

EPIC-018 평가에서 확인한 제품의 범위와 한계다. 아래 항목을 해결된 보안 주장으로 표현하지 않는다.

- `PROCESS` 증거는 정확한 파일 Writer를 증명하지 않는다.
- 사후 파일시스템 감지는 사전 예방이 아니다.
- AIA에 연결되지 않은 Hook 우회 경로와 지원 범위 밖 도구는 보호되지 않는다.
  보호 실행에 바인딩된 동기식 PreToolUse Hook은 Broker·Capability 오류 시 Codex의
  documented blocking exit path를 사용하고 Broker가 사라진 실행은 검증 상태를
  유지하지 않지만, PostToolUse 오류는 이미 실행된 작업을 되돌릴 수 없고 Hook 우회
  경로를 OS 수준에서 차단하지 않는다.
- MCP 도구는 현재 MVP 지원 범위가 아니다. Hook으로 도착한 MCP 요청은
  `UNSUPPORTED_TOOL_PATH`로 거부하며, MCP 서버 등록·호출이나 구조화된 MCP READ
  보호를 제품 기능으로 주장하지 않는다.
- Codex에서 켠 외부 도구(MCP 서버)의 도구 호출은 보호 범위 밖이다. Codex 앱이 추가하는
  `node_repl` 같은 일부 MCP 도구는 PreToolUse Hook을 거치지 않아 AIA가 차단하거나
  기록하지 못한다. 그래서 Workbench 보호 실행은 외부 도구를 기본으로 끈 채 시작한다.
  `config.toml`의 `[mcp_servers]`, 캐시된 플러그인의 MCP 서버, ChatGPT 앱 연결(`codex_apps`)을
  읽기만 해서 찾고, 그 실행의 `codex app-server`에만 끄는 `-c` 값을 넘긴다(Codex 설정 파일은
  바꾸지 않는다). 사용자가 설정 › 외부 도구에서 켠 도구만 켜지고, 켠 도구는 여전히 보호 범위
  밖이다. 플러그인 도구는 플러그인 단위로만 끌 수 있고, `-c` 경로로 쓸 수 없는 이름(점이 든
  이름 등)은 끌 수 없어 켜진 것으로 경고한다. 처음 보는 도구도 꺼진 상태로 시작한다.
- 전체 권한(사용자의 명시적 선택)에서는 Codex Sandbox가 작업 폴더 밖 쓰기와 인터넷 사용을 막지 않는다. 기본값은 승인 요청이다.
  AIA는 지원되는 Hook 요청만 검사하며 OS 수준에서 모든 경로를 막지 않는다. 작업 폴더 밖 변경은 기준점·복구
  범위 밖이다. 결과에는 `CODEX_FULL_ACCESS_USER_SELECTED`로 남는다.
- "나 대신 승인"에서는 Codex 자동 검토가 승인 요청(Sandbox 밖 쓰기·네트워크 등)을 대신 판단한다. 그렇게
  승인된 권한 확대는 사용자 허용과 달리 AIA 권한 기록(`permission_grants`)에 남지 않을 수 있다. 결과에는
  `CODEX_AUTO_REVIEW_USER_SELECTED`로 남고, 자동 검토 결과 알림은 Codex가 아직 불안정한 형식이라고 밝힌
  상태라 결과(승인·거절·위험도)만 대화에 보여 준다.
- Codex Windows 샌드박스는 명령을 실행할 때마다 Codex 앱 런타임(`node_repl.exe` 등)의 권한을
  점검한다. Codex 앱이나 백그라운드 app-server(daemon)가 `node_repl`을 실행 중이면 이 점검이
  파일 잠금으로 실패해 모든 셸 명령이 `setup refresh had errors`로 실패할 수 있다. AIA 보호
  실행은 `node_repl`을 끄지만 다른 Codex 프로세스의 잠금은 풀 수 없으므로, 이때는 Codex 앱을
  종료하고 `codex app-server daemon stop`으로 백그라운드 서버를 멈춰야 한다.
- Windows Job Object와 프로세스 수명주기는 테스트 실행 환경에 영향을 줄 수 있다.
- Symlink/Junction/Reparse Point 범위는 거부 계약과 환경 독립 테스트로 검증했으며, 권한 없는 Windows 환경의 실제 Symlink 통합 테스트는 실행되지 않을 수 있다.
- OS 수준의 파일 Writer 귀속은 제공하지 않는다.
- File Sensor는 `modified` 이벤트가 온 파일의 크기와 SHA-256이 마지막으로 알려진 내용
  (실행 전 Checkpoint)과 같으면 권한·속성만 바뀐 것으로 보고, 원시 증거에
  `content_unchanged`로 남기되 MODIFY 행위로 판정하지 않는다(Codex 샌드박스의 ACL 추가 등).
  비교는 이벤트를 처리하는 시점의 내용 기준이므로, 그 전에 내용을 바꿨다 똑같이 되돌린 경우도
  수정으로 보지 않는다. Checkpoint에 없거나 32MB를 넘거나 읽을 수 없는 파일, 한 번이라도
  내용이 달라진 파일, 폴더 이벤트는 기존처럼 수정으로 판정한다.
  파일 및 상위 경로의 링크·Reparse Point와 비교 중 관찰된 파일 교체·변경은
  내용 동일로 처리하지 않는다. 읽기는 예상 크기 + 1바이트로 제한한다.
  비교 전후 검사는 원자적 스냅샷이 아니므로 모든 외부 Writer race를 방지하지는 않는다.
- 보호 경계 실패 시 AIA가 관리 Root 트리 중지를 시도하지만, 종료 성공 자체를 보장하지 않는다.
- Network Security는 MVP 보호 범위가 아니다.
- Database state protection은 제공하지 않는다.
- ACL/ADS 메타데이터 복구를 보장하지 않는다.
- 전체 Workspace에 대한 원자적 트랜잭션은 제공하지 않는다.
- 외부 Writer race 및 TOCTOU는 제한사항이다.
- GB 단위 Workspace 성능 목표나 SLA를 주장하지 않는다.
- 정책 위반에 따른 Actual Codex의 자동 destructive `PROCESS` 집행은 아직 검증하지 않았다. 다만 실제 Codex 사용자 중지 경로에서는 등록된 Root → Child → Grandchild 트리 종료와 unrelated 프로세스 보존을 확인했다. 이 결과를 정책 위반 자동 집행의 성공으로 해석하지 않는다.

### Codex 작업 경험 보강(EPIC-022)의 범위

- **권한 추가 요청을 허용한 범위:** 사용자가 허용한 작업 폴더 밖 쓰기와 인터넷 사용은 AIA 기준점·복구와 감시 범위 밖이다.
  - 결과 화면은 허용 사실을 보여줄 뿐, 그 범위의 안전을 보장하지 않는다.
  - 권한 허용 결정은 Codex에 전달하기 전에 런타임 기록에 저장한다. 저장 실패 시 허용하지 않는다.
  - 한 번이라도 추가 권한을 허용한 실행은 보수적으로 보호 제한 상태(`DEGRADED`)로 표시한다.
    최종 Result Bundle에는 `CODEX_PERMISSIONS_USER_GRANTED` 제한을 남긴다. 세부 권한·선택 시각은
    별도의 런타임 기록이며, 센서 증거나 봉인된 Bundle의 세부 감사 기록과 같다고 주장하지 않는다.
  - 해당 실행에서는 추가 자동·수동 복구 지점을 저장하지 않는다. 실행 전 기준점과 기존 복구 지점은 유지하며,
    작업 폴더 밖 변경이나 네트워크 부작용은 복구하지 못한다. 기존 Hook 정책을 완화하지 않는다.
  - 질문·외부 도구 입력·권한 요청 대기 중에는 추가 복구 지점을 저장하지 않으며,
    복구 지점 복사 중에는 해당 응답도 명령 입력과 같은 잠금으로 대기한다.
- **입력값의 행방:** 질문 답과 외부 도구 입력값은 Codex와 해당 도구에 전달된다.
  - AIA는 비밀 답과 입력값을 이벤트·기록·진단 정보에 남기지 않는다.
  - 받은 쪽이 그 값을 어떻게 쓰는지는 보장하지 않는다.
- **Codex가 알려준 정보:** 사용량, 모델 목록, 작업 계획, 바뀐 내용(diff)은 Codex가 알려준 값이다. AIA가 독립적으로 검증하지 않는다.
  - 바뀐 내용 글은 메모리에만 두고(요청 30개, 50만 자까지) 저장하지 않는다.
  - 파일 변경 증거는 기존처럼 파일 센서 기준이다.
- **모델 목록과 이어하기 목록:** 스레드를 열지 않는 임시 Codex 앱 서버로 읽는다. 이 프로세스는 보호 실행 밖에서 잠깐 실행된다.
- **이전 대화 이어하기**
  - 이전 대화에서 일어난 일은 이번 실행의 보호 기록 범위 밖이다.
  - AIA는 대화 번호만 저장하고 대화 글은 저장하지 않는다.
- **큰 작업 폴더:** 시작할 때 기준점 저장·준비 확인·Codex 시작 직전 재확인으로 폴더 전체를 여러 번 해시한다.
  - 파일이 많으면 시작이 느리다. 이 재확인은 확인과 사용 사이의 틈을 막는 보안 검사라 줄이지 않았다.
- **실제 Codex로 아직 확인하지 않은 것**
  - Codex가 실제로 질문·외부 도구 입력·권한 추가 요청을 보내는 경우
  - 내용이 있는 대화를 이어 쓰는 경우
  - 이 경우들은 가짜 Codex 앱 서버로만 확인했다. 실제 Codex로는 요청 없이 대화 연결·사용량·생각 깊이·커넥터 목록·대화 번호 기록만 확인했다(2026-10-07).

이 제한사항은 `docs/validation/CLAIM-MATRIX.md`의 허용 문구와 함께 읽어야 한다.
